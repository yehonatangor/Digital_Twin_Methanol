# Sampling and dataset design

A single dataset provides the input data for both surrogate regression and feasibility classification. The dataset is generated by sampling the bounded design box, solving each design point on the digital twin, recording convergence states, and saving the resulting table alongside a provenance sidecar.

## 1. Design vector

Eleven operational and design parameters are sampled in fixed column order: `n_tubes`, `tube_inner_diameter_m`, `bed_length_m`, `reactor_inlet_T_K`, `reactor_inlet_P_bar`, `recycle_fraction`, `co2_feed_kg_s`, `fresh_h2_to_co2_ratio`, `activity`, `total_stages`, and `h2_storage_volume`. The electricity price dispatch schedule is treated as a fixed boundary condition across sweeps. Design variables map directly to pybind keyword arguments: `total_stages` maps to `n_trays`, and `h2_storage_volume` maps to `storage_volume_m3`.

## 2. Sampling method

The default sampler uses Latin hypercube sampling via `scipy.stats.qmc` to distribute points across the hypercube. Sobol sequences are available when sample budgets are powers of two. Random seeds ensure full determinism. The `--wide` flag expands four operational boundaries (pressure up to 90 bar, temperature up to 545 K, recycle fraction up to 0.97, and relative activity down to 0.35) to capture off-design behavior.

## 3. Data schema

| Group | Variables | Description |
|---|---|---|
| Features | 11 design variables | Complete set of input coordinates |
| Targets | `unit_cost_USD_per_t`, `co2_conversion_overall`, `meoh_product_kg_s`, `annual_production_t`, `total_electricity_MW` | Computed on feasible points; NaN for failed evaluations |
| Classification | `feasible`, `outcome_code`, `outcome_token` | Integer codes follow the digital twin outcome taxonomy |
| Validity | `within_validated_range`, `worst_relative_excursion` | Measures distance beyond the validated thermodynamic correlations |
| Sample weight | `sample_weight` | Continuous weight defined by $w = \exp(-4\,e)$, where $e$ is worst relative excursion |
| Provenance | `fp` columns | Subsystem fingerprint hashes identifying the C++ twin build |

## 4. Class distribution and sample weighting

Failed evaluations remain in the dataset to train the feasibility classifier. In the 6000-point physical run, 5715 points solved successfully (95.2% feasibility) and 285 points failed (`recycle_not_converged`: 116, `reactor_clamp_violation`: 104, `reactor_rhs_failure`: 65).

The sample weighting factor down-weights design points that exceed validated kinetic and thermodynamic correlations. The surrogate trains with higher priority on validated regimes while decaying smoothly near correlation boundaries. Because the sample space encompasses pressures up to 78 bar and the Langmuir-Hinshelwood kinetics correlation boundary sits at 75 bar, points above 75 bar receive fractional weights without truncation.

## 5. File format and storage

Data is stored as a Parquet table with CSV fallback. A companion metadata JSON file stores parameter bounds, column names, sampling method, random seed, row count, and contract hash. Feasible rows are filtered for surrogate training, while the complete table trains the feasibility classifier.
